1.1 使用STM32CubeMX生成Cmake工程，使用Clion作为开发环境，内置STM32的支持，可以一键编译，调试，烧录;
实际工具链是arm-gnu-toolchain-15.3，路径C:\arm-gnu-toolchain-15.3\;
构建入口arm-none-eabi-gcc，烧录入口OpenOCD，调试入口arm-none-eabi-gdb;
1.2 NUCLEO-F401RE时钟配置，16MHz外部晶振通过PLL倍频得到84MHz，于是整个系统的时钟频率是84MHz;
1.3 流水灯设计是每500ms一拍，总计8个LED，设计一个周期是4s，使用逻辑分析仪抓到的时序，实际一个周期是3.96s，应该是计时误差;
2.1 startup_stm32f401xe.s是启动文件，提供向量表和复位处理代码，建立运行环境后调用 main();
STM32F401xx_FLASH.ld是链接脚本，在工程根文件夹下面，告诉链接器如何布置代码、数据和内存区域，并定义相关符号;
system_stm32f4xx.c位于Core/Src文件夹下面，是系统初始化文件，作用是初始化时钟，配置时钟，配置中断向量表;
main.c是核整个程序的逻辑入口与核心框架文件，包含应用层入口与当前业务逻辑；业务代码以后可以拆到其他文件;
3.1 编译成功、烧录成功、程序正确运行，各自证明了什么？
编译、链接成功，说明源码通过当前工具链检查，所需符号能够解析，生成了输出文件;
烧录成功，说明工具将数据写入了目标存储器；若执行校验，还说明读回内容匹配;
实测运行符合预期，说明在本次输入、接线和运行条件下，观察到的行为符合要求;
3.2 启动文件、链接脚本与 main.c 分别大致负责什么？
启动文件，提供向量表和复位处理代码，建立运行环境后调用 main();
链接脚本，告诉链接器如何布置代码、数据和内存区域，并定义相关符号;
main.c，包含应用层入口与当前业务逻辑；业务代码以后可以拆到其他文件;
3.3 暂停 CPU 后，LED 和计数器有什么表现？这说明当前闪烁依赖什么？
调试器暂停 CPU 后，CPU 不再执行流水灯切换和计数器递增指令。GPIO 保持此前的输出状态，因此 LED 停在当前位置，计数器保持不变;
4.1 流水灯实际运作符合设计要求，按下开发板上的Reset按钮，以及重新上电，流水灯均可正常重新运作。
